## Levers, with the qualifications that cost me time

1. **Block/arm ordering.** MWCC lays switch cases and if/else arms out in source
   order. On any large switch this is the first thing to check. Sweep the arm
   through candidate positions — I have never guessed the right one first try.
2. **Out-of-line error paths.** `if (ok) { ... } else { fail; }` puts `fail` at
   the bottom, matching retail's branch-away layout. Worth 3–11pp repeatedly.
3. **`#pragma peephole off`** — sweep it mechanically per function. 29 wins in
   the PDA. `scheduling off` lost in every one of ~15 comparisons. Track pragma
   state *linearly* through the file; grepping preceding lines wrongly skips
   every function after another's `reset`.
4. **`x | -0x100LL`** gives retail's `li`+`or` instead of `oris`/`ori` — **only
   where the result stays 32-bit.** Cast to `(void*)` it costs an extra `srawi`.
   Split by destination type; on `fn_800411FC` that was 76.44 (all LL) / 77.60
   (no LL) / **79.62 (split)**. Lost through an inline helper's `s32` parameter.
5. **Global address caching is per-function, not a rule.** Removing `u8* S =
   &lbl_...` won +11.6pp on `fn_80048918` and lost 9pp on `fn_8003B2D8`. Measure
   both directions, every time.
6. **Argument evaluation order.** MWCC evaluates call args right-to-left;
   sequencing them into locals first flips it to match retail.
7. **Unsigned division.** `u16 x; x / 10` promotes to int and emits the *signed*
   magic. Cast to `(u32)` for retail's `mulhwu`.

**Targeted edits beat rewrites.** A full rewrite of `fn_8003B2D8` incorporating
every correct insight scored *below* baseline (73.99 vs 75.09); the same
insights applied separately and swept 2³ ways found 84.46. Bundle wins with
losses and you cannot tell them apart.

## Traps

- **Score-neutral ≠ no-op.** I twice concluded a change did nothing because the
  percentage held, when the instruction order had in fact moved to match retail.
  For anything that should reorder code, diff the *sequence*.
- **Symbol naming does not affect fuzzy_match_percent.** objdiff resolves
  relocations by address. Don't chase `fn_ADDR` vs real names for score.
- **Merge resolution:** when taking one side of a conflicted file wholesale,
  check what upstream *modified*, not only what it *added*. #493 discarded two
  round-59 fixes that had taken functions to 100% and the gate caught it.
- Clang `-Wimplicit-function-declaration` on these files is **not** noise; a
  missing `extern u8 fn_801429E8(...)` was a real 4pp regression.
- Anchors like `case 0x760:` occur in several functions — scope edits to the
  function body, and match definitions at line start (a forward `extern`
  declaration will match a naive regex).
